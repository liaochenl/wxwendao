# 《五行问道》移动端适配设计规格

- 日期：2026-10-18
- 类型：现有静态 Web 游戏的移动端适配（玩法与数据不变）
- 目标设备：iPhone 15 Pro 竖屏 393×852（Safari 可视高度约 750），兼容 375×667 与 430×932
- 桌面端约束：>600px 的布局、视觉与交互保持不变

## 1. 背景

《五行问道》当前按桌面 1280×800 设计，虽有三档响应式断点（1200/1060/900），但没有针对手机的布局规则。以 iPhone 15 Pro 的 393×852 视口实测，出现两类硬伤：

- 地图页布局宽度被撑到 566px，`body` 又设置了 `overflow-x: hidden`，顶部「牌组 / 遗物 / 设置」三个按钮整体位于屏幕外且无法横向滚动到达。
- 战斗页手牌按桌面尺寸叠放，最右一张被「结束回合」按钮压住，左下牌堆/丹药托盘被手牌完全遮住。

此外，触控目标偏小（31–42px），悬停样式在触屏上会粘住，页面高度使用 `100vh`，未处理安全区。这些问题共同导致手机端"能打开但不好玩"，因此做一轮系统适配。

## 2. 现状审计（393×852，DPR 3）

基线截图：[地图](../../screenshots/mobile-audit/map-393.png) · [战斗](../../screenshots/mobile-audit/combat-393.png)

| 页面 | 实测结果 | 结论 |
|---|---|---|
| 标题 / 选人 | `scrollWidth = 393`，无溢出 | 基本可用，仅需安全区与 44px 目标 |
| 地图 | 布局宽 **566px**；`.hud-actions` 位于 **x=433–566**；`.map-canvas` 固定 `min-width: 420px` | 按钮出屏、右侧节点被裁，必须重排 |
| 战斗 | 屏高 **897px**；手牌 138×198、间距 53px；结束回合 132×46 叠在手牌上；托盘被遮 | 操作冲突，必须重排 |
| 战斗/面板 | 卡面正文 10px，状态标签 8–10px；顶部按钮 40×42，关闭按钮 52×31 | 低于可读性与 44pt 触控标准 |

其他已确认可用、不需要改动的部分：

- 单页静态、零外部请求；`file://` 可运行。
- 敌人区、玩家面板在 900px 断点下会自动堆叠。
- 点击出牌、选目标、结束回合在触屏上均可触发（事件委托使用 `click`）。
- 音频在首次 `pointerdown` 解锁，移动端可用。
- 存档使用 `localStorage`，与布局无关。

## 3. 目标与非目标

### 3.1 目标

1. 393×852 下所有页面 **无横向溢出**，所有可操作元素完整可见。
2. 战斗页在一屏内完成看敌人意图、看连携、出牌、结束回合；手牌不被任何控件遮挡。
3. 触控目标 ≥44×44（至少一个维度），手牌卡面正文 ≥11px。
4. 消除触屏上的悬停残留、双击缩放、下拉刷新干扰。
5. 适配 iPhone 刘海与 Home 指示条（安全区），兼容 Safari 地址栏收放。
6. 桌面端零回归。

### 3.2 非目标

- 不做横屏专属布局；横屏沿用现有窄桌面布局。
- 不改规则、卡牌/敌人数据、平衡、存档结构。
- 不做 PWA / 离线缓存 / 主屏安装（后续可独立做）。
- 不重做美术、不做新手引导、不加长按查看卡牌详情。
- 不引入任何运行时依赖或构建步骤。

## 4. 设计原则

1. **CSS 优先**：优先通过媒体查询重排现有 DOM；只有手牌宽度计算必须改 JS。
2. **桌面隔离**：所有移动规则限定在 `max-width: 600px`；`hover` 效果统一加媒体查询保护。
3. **触控优先但不牺牲键盘**：保留数字键、`E`、`Esc` 快捷键；移动端只是不提示。
4. **可读性下限**：卡面正文 11px、辅助文字 11px、正文 14px；不靠整体缩放适配。
5. **渐进增强**：`100dvh/100svh` 在支持时生效，`100vh` 兜底；内容超出时允许纵向滚动，绝不裁切。

## 5. 断点

| 断点 | 用途 |
|---|---|
| `max-width: 600px` | 手机主断点，本规格全部规则 |
| `max-width: 900px` | 现有平板/窄桌面规则，保留 |
| 1060 / 1200 / `max-height: 780px` | 现有桌面规则，保留 |

- 手机规则在文件中放在现有断点之后，确保覆盖。
- 不使用 `max-height` 隐藏内容；小屏通过纵向滚动兜底。

## 6. 战斗页

### 6.1 结构（从上到下）

| 区域 | 高度 | 内容 |
|---|---|---|
| 顶部栏 | 40px | 回合标签、幕名、牌组/遗物/设置（44×44） |
| 敌人区 | 190px | 意图条 + 敌人卡（名、五行、HP、状态） |
| 玩家条 | 76px | 头像 44、姓名/被动、血条、状态、遗物 |
| 连携行 | 48px | 当前五行→下一行、连携 0/5、灵气球 |
| 手牌区 | 170px | 手牌横向滑动 |
| 工具行 | 56px | 丹药 3×44、抽/弃/灭 3×48×56 |
| 结束回合 | 52px | 整行大按钮 |
| 提示行 | 18px | 出牌/选目标提示 |

总高约 700px，393×852 下无需滚动；Safari 地址栏展开（约 750px）时仍完整可见。更矮的设备允许纵向滚动。

### 6.2 尺寸与排版

- 手牌：**116×162**，牌名 13px、正文 **11px**、立绘 46px、费用 24px。
- 手牌排列：**不重叠**、无旋转、间距 8px，横向滚动；初始显示约 3 张，可滑动查看全部。
- 敌人：单敌 300px 宽；2 敌各 165px；≥3 敌横向滚动，不换行增高。意图条高 30px，立绘 48px。
- 结束回合：整行宽、高 52px，字号 15px；不再绝对定位。
- 丹药/牌堆：从绝对定位改为手牌上方一行，`space-between` 布局。
- 卡面文字不得截断关键词（伤害、格挡、中毒等）；手牌字号固定 11px，不随牌数缩小。

### 6.3 交互

- 单敌人：点击手牌直接打出。
- 多敌人：第一次点牌进入选中态（牌抬起 8px + 金边），再点敌人打出；点击空白处取消选中。
- 横向滑动手牌不触发出牌：依赖浏览器在滚动后抑制 `click`，并设 `touch-action: pan-x`。
- 结束回合按钮在敌方回合禁用（现有逻辑）。
- 覆盖层（牌组/遗物/设置/牌堆）打开时覆盖全屏，关闭按钮 44×44。
- 键盘快捷键保持不变。

### 6.4 JS 变更

`js/ui.js` 的 `combatHTML()` 中手牌尺寸计算增加移动分支：

- 移动端（`innerWidth <= 600`）：`cardW = 116`、`overlap = 0`。
- 桌面端保持现有公式不变。
- 目的：避免内联 `margin-left` 与 CSS 冲突，不使用 `!important`。

### 6.5 纵向适配

- `.combat-screen` 在手机端改为 `height: auto; min-height: 100vh; min-height: 100svh;`，允许滚动。
- 不使用固定 `100vh` 裁切；手牌区不设固定高度上限，按内容撑开。

## 7. 地图页

### 7.1 HUD

两行网格：

```
第一行： 头像 + 姓名/幕名       金币   天劫
第二行： 血条（跨两列）        牌组 遗物 设置（44×44）
```

- 使用 CSS Grid，`grid-template-areas: "char gold asc" "hp hp actions"`。
- 血条宽度自适应，最小 120px。
- 三个按钮不再溢出，始终可点。

### 7.2 侧栏瘦身

保留：

- 幕名（`第一幕 · 山门问道`）
- 幕主信息（名称 + 五行）
- 丹药三格

隐藏（移动端）：

- 幕间说明文字（`.act-flavor`）
- 图例（`.map-legend`）
- 重复的按钮组（`.map-actions`）
- 底部提示框（`.map-tip`）

侧栏改为横向紧凑条，高度约 64px。

### 7.3 地图画布

- 移除 `.map-canvas { min-width: 420px }`，宽度 100%。
- 节点从 58×58 提升到 **64×64**；Boss 节点 80×80。
- 节点标签 11px，保持白色不换行。
- 节点横向位置为百分比，画布变窄时自动压缩；纵向间距保持 112px。
- 滚动区高度 `calc(100svh - 230px)`，保留进入时自动定位当前节点。

## 9. iOS 与触控规范

| 项 | 规则 |
|---|---|
| viewport | `width=device-width, initial-scale=1, viewport-fit=cover` |
| 安全区 | `.screen` 使用 `padding: max(14px, env(safe-area-inset-top)) max(14px, env(safe-area-inset-right)) max(14px, env(safe-area-inset-bottom)) max(14px, env(safe-area-inset-left))`；toast 底部 `calc(24px + env(safe-area-inset-bottom))`；覆盖层同样处理 |
| 视口高度 | 优先 `100dvh`/`100svh`，`100vh` 兜底；禁止把内容锁死在固定高度 |
| 悬停 | 所有 `:hover` 位移/发光规则包进 `@media (hover: hover) and (pointer: fine)` |
| 按压反馈 | 手机端可点元素加 `:active`：背景提亮或缩放 0.98，持续 120ms |
| 双击缩放 | 可点元素 `touch-action: manipulation`；手牌区 `touch-action: pan-x` |
| 下拉刷新 | `body { overscroll-behavior: none }` |
| 点击高亮 | `-webkit-tap-highlight-color: transparent`，保留 `:focus-visible` 描边 |
| 触控目标 | 按钮/选项/节点 ≥44px；牌堆 48×56；丹药 44×44 |
| 字号 | 手牌卡面正文 ≥11px、浏览态卡面 10.5px、辅助文字 ≥11px、正文 14px；不改变浏览器缩放 |
| 横屏 | 不加规则；不显示强制旋转遮罩 |

## 11. 验收标准

### 11.1 自动断言（393×852 与 430×932）

1. 标题、选人、地图、战斗、奖励、商店六类页面：`document.documentElement.scrollWidth <= innerWidth + 1`。
2. 所有可见 `[data-action]` 元素：宽或高 ≥44px。
3. 战斗页：结束回合按钮与手牌区完全位于视口内，且两者矩形不相交。
4. 地图页：`.hud-actions` 右边缘 ≤ 视口宽度。
5. 手牌 `.card-text` 计算字号 ≥11px。
6. 桌面 1280×800：战斗、地图、奖励三张截图与适配前对比，布局无变化。

> 审计脚本默认使用 macOS 的 Google Chrome；其他平台通过 `CHROME_BIN` 指定浏览器可执行文件。

### 11.2 单元测试

`npm test` 31 项全部通过；不新增规则测试（无规则变更）。

### 11.3 真机清单（iPhone 15 Pro / Safari）

- 新建轮回 → 选人 → 进入地图：顶部三按钮可点，地图节点无裁切。
- 战斗：5 张手牌可滑动、可点击；多敌人时选牌→点敌人可出牌；结束回合可点。
- 打开牌组/遗物/设置/牌堆覆盖层：内容可滚动，关闭按钮可点。
- 奖励页：三张牌同排，选中后可继续。
- 商店：两列卡牌可购买，法器/丹药单列。
- 刷新页面：继续修行，进度不丢。
- 安全区：刘海不遮挡顶部，Home 指示条不遮挡结束回合。
- 无横向滚动、无双击缩放、无下拉刷新。

## 12. 测试方式

1. `npm test`：规则回归。
2. `npm run audit:mobile`：启动本地静态服务与 headless Chrome，遍历六类页面，断言 11.1 的 1–5 项，并在 `docs/screenshots/mobile-audit/` 输出截图；失败时以非零码退出。
3. 桌面回归：`1280×800` 截图人工对比。
4. 真机：按 11.3 清单逐项确认。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 手牌滑动误触出牌 | `touch-action: pan-x`；滚动后浏览器抑制 click；真机验证 |
| 内联手牌 `margin-left` 覆盖 CSS | 移动分支直接输出 `overlap = 0`，不用 `!important` |
| iOS `100vh` 与地址栏 | 使用 `svh/dvh` + 允许滚动，不锁高度 |
| 触屏 hover 粘住 | `(hover: hover)` 包裹所有悬停位移；`:active` 提供反馈 |
| 安全区在 Safari 与全屏不一致 | 使用 `env()` + `max()`，浏览器内为 0 时自然退化 |
| 桌面被新规则影响 | 所有规则限定 600px；改完先跑桌面截图对比 |
| 小屏（375×667）放不下 | 允许纵向滚动；结束回合仍在文档流末尾，不被遮挡 |
