# 《五行问道》设计规格

- 日期：2026-10-17
- 类型：单机 Roguelike 卡牌构筑
- 平台：桌面浏览器，纯 HTML/CSS/JS，零依赖，本地双击即玩
- 单局时长：约 30–40 分钟（三幕）

## 1. 目标与体验

玩家扮演一名修真者，在三幕分支地图中闯关。战斗的核心不是单纯堆数值，而是**在「维持五行相生连携」与「断链用相克打弱点」之间做取舍**。每一局因角色、卡牌奖励、遗物、事件与地图不同而形成不同流派。

成功的标准：

- 新玩家 1 分钟内理解出牌与相生连携；
- 老玩家能主动规划下回合的元素顺序、卡组浓度与遗物联动；
- 三种角色有明确不同的节奏；
- 单局失败也有「下一局换个流派」的冲动；
- 无死锁、无卡死、刷新可续局。

## 2. 核心规则

### 2.1 战斗流程

1. 战斗开始：玩家与敌人获得战斗开始效果；玩家抽牌堆洗牌。
2. 玩家回合开始：护甲清零（角色/遗物/卡牌保留的护甲除外），结算中毒、回春等回合开始状态，灵气重置为 3（受遗物影响），抽 5 张（受遗物/状态影响），手牌上限 10。
3. 玩家可任意顺序打出卡牌、使用丹药。出牌立即结算。
4. 结束回合：结算回合结束状态（灼烧、回春），弃掉手牌（保留牌除外）。
5. 敌人回合：敌人护甲清零，按意图行动；意图在玩家回合全程可见。
6. 回到玩家回合。

### 2.2 五行与相生连携

五行及颜色：

| 元素 | 色 | 相生（我生） | 相克（我克） |
|---|---|---|---|
| 木 | 青绿 | 火 | 土 |
| 火 | 赤红 | 土 | 金 |
| 土 | 土黄 | 金 | 水 |
| 金 | 月白/金 | 水 | 木 |
| 水 | 靛蓝 | 木 | 火 |
| 无 | 灰 | — | — |

规则：

- 每张牌有且仅有一个元素（或无）。
- 战斗内维护 `currentElement`（当前五行）与 `chain`（连携层数，0–5）。
- 打出一张有元素的牌时：
  - 若 `currentElement` 非空且 `相生(currentElement) === 牌元素`：`chain += 1`（上限 5），该牌获得 **+chain** 的伤害/格挡加成；随后 `currentElement = 牌元素`。
  - 否则：`chain = 0`，该牌无连携加成；`currentElement = 牌元素`。
  - 首张牌：`currentElement` 为空，`chain = 0`，无加成，随后设为该牌元素。
- 打出的牌若无元素：不改变 `currentElement`，不改变 `chain`，也不获得连携加成。
- 连携达到 5 时，在卡牌结算后触发 **「五行周天」**：对所有敌人造成 8 点无视护甲的伤害，获得 1 灵气，抽 1 张牌，然后 `chain = 0`（`currentElement` 保留为刚打出的元素）。每张牌至多触发一次。
- UI 必须显示：当前五行、下一张可续链的元素、连携层数、达到周天还差几层。

### 2.3 相克

- 攻击牌命中敌人时，若牌元素克敌人元素：该次伤害 ×1.5（向下取整）且**无视敌人护甲**。
- 多目标攻击对每个敌人分别判定。
- UI 在敌人与卡牌上显示「克制」提示与预计伤害。

### 2.4 伤害结算顺序

`最终伤害 = floor((基础值 + 锐气 + 连携加成) × 虚弱系数 × 相克系数 × 易伤系数)`

- 虚弱：×0.75（向下取整）。
- 相克：×1.5。
- 易伤：×1.5。
- 敌人护甲先行吸收；相克攻击无视护甲。
- 多段攻击每段单独加算锐气与连携、单独结算护甲。
- 中毒伤害无视护甲。

### 2.5 状态

| 状态 | 效果 | 时机 |
|---|---|---|
| 护甲 | 抵挡伤害 | 玩家回合开始清零（保留值除外） |
| 锐气 | 每次攻击 +N 伤害 | 永久（战斗内） |
| 坚韧 | 每次获得护甲 +N | 永久（战斗内） |
| 中毒 | 回合开始失去 N 生命，无视护甲，随后 N−1 | 回合开始 |
| 灼烧 | 回合结束失去 N 生命，随后 N−1 | 回合结束 |
| 虚弱 | 造成攻击伤害 ×0.75，回合结束 N−1 | 持续 N 回合 |
| 易伤 | 受到攻击伤害 ×1.5，回合结束 N−1 | 持续 N 回合 |
| 回春 | 回合结束回复 N 生命，随后 N−1 | 回合结束 |
| 荆棘 | 被攻击时对攻击者造成 N 伤害 | 受击时 |
| 蓄势 | 回合开始获得 N 锐气 | 回合开始 |
| 定身 | 跳过下一次行动 | 敌人回合 |

状态层数在 UI 中显示为图标 + 数字，悬停解释。

### 2.6 卡牌

- 类型：攻击、技法、身法、禁制（诅咒）。
- 费用 0–3。
- 稀有度：初始、普通、罕见、稀有、诅咒。
- 每张非诅咒牌都有升级版：数值提升、费用降低或附加效果。
- 关键词：
  - **消耗**：结算后移出本场战斗。
  - **保留**：回合结束不弃置。
  - **贯穿**：无视护甲。
  - **连携**：按当前连携层数产生额外效果。
  - **周天**：与五行周天相关。
- 初始牌组 10 张；卡牌奖励三选一，可跳过。

### 2.7 角色

| 角色 | 元素 | 生命 | 被动 | 初始牌组 |
|---|---|---|---|---|
| 剑修·凌霄 | 金/水 | 72 | 剑心：每回合第一张攻击牌结算后，对其目标额外造成 4 点伤害 | 金刃斩×5、流云护×4、断岳×1 |
| 丹修·青萝 | 木/火 | 66 | 药心：每次施加中毒额外 +1 层 | 缠丝诀×5、赤炎符×4、百草回春×1 |
| 体修·磐石 | 土/金 | 84 | 厚土：回合开始时护甲最多保留 4 点 | 岩拳×5、金钟罩×4、山岳崩×1 |

角色专属卡（各 3 张）加入对应角色的奖励池；通用卡三人都能获得。每位角色额外自带一件初始遗物：青锋剑穗（攻击伤害 +1）、药囊（战斗开始获得 1 层回春）、铁甲片（战斗开始获得 6 点护甲）。

### 2.8 遗物与丹药

- 遗物为被动，触发时机：战斗开始、回合开始、出牌、连携、击杀、战斗结束、休整、商店、奖励。
- 丹药为一次性消耗品，仅战斗中可用，腰带 3 格。
- 丹药类型：回春丹（回复 15）、烈焰丹（对单体 20 伤害）、龟息丹（获得 15 护甲）、聚气丹（+2 灵气）、洗髓丹（抽 3）、化毒丹（清除自身负面并回复 5）、破妄丹（+2 锐气）、五行丹（当前连携 +2，若达到 5 立即触发周天）。

## 3. 地图与流程

### 3.1 一局结构

三幕，每幕 8 层 + Boss 层：

- 第 0 层：3 个战斗节点（起点三选一）。
- 第 1–6 层：每层 2–3 个节点，类型从战斗、精英、事件、商店、休整、宝箱中抽取。
- 第 4 层固定含 1 个宝箱；第 7 层固定为休整。
- 第 8 层：Boss。
- 节点间连线，玩家只能前往当前节点连通的下一层节点。
- 每幕节点类型分布：战斗约 50%，精英 10%，事件 15%，商店 8%，休整 12%，宝箱 5%。

### 3.2 节点

- **战斗**：普通敌人 1–2 个；奖励金币 + 卡牌三选一，概率丹药。
- **精英**：精英敌人；奖励遗物 + 金币 + 卡牌。
- **事件**：文字事件，2–3 个选项，有代价与收益；部分需要金币/生命/卡牌。
- **商店**：3 张卡、2 个遗物、3 瓶丹药、1 次删牌服务；价格随幕数上涨。
- **休整**：回复 30% 最大生命，或升级一张牌；可查看牌组。
- **宝箱**：随机遗物或金币/丹药。
- **Boss**：幕末强敌；击败后进入下一幕，回复 25% 最大生命并选择一张稀有卡。

### 3.3 奖励与商店

- 战斗金币：12–20（随幕数增加）。
- 卡牌奖励稀有度权重：普通 60 / 罕见 30 / 稀有 10；精英与 Boss 提升稀有概率。
- 遗物奖励不重复；已拥有遗物从池中移除。
- 商店价格：卡 45–70，遗物 140–200，丹药 50–70，删牌 75（每次 +25，每店一次）。
- 金币不足时按钮禁用并提示。

### 3.4 天劫（难度）

首次通关解锁天劫 1 级，最高 10 级。天劫 N：

- 敌人生命 +4%×N，伤害 +2%×N；
- 天劫 6–9 起始获得 1 张「杂念」，天劫 10 获得「杂念」与「心魔」各 1 张；
- 金币获取 −2%×N（向下取整）；
- 解锁记录本地保存。

## 4. 内容清单

- 卡牌：≥60 张（含初始、普通、罕见、稀有、诅咒），全部可升级。
- 遗物：≥18 个。
- 普通敌人：≥18 个，覆盖三幕与五行。
- 精英：≥3 个（每幕一个）。
- Boss：3 个，各有阶段/特殊机制。
- 事件：≥12 个。
- 丹药：8 种。
- 诅咒：3 种。
- 图鉴：记录已见卡牌、遗物、敌人。

Boss 设计：

1. **山鬼·魑**（土，第一幕）：高护甲与岩崩；半血后进入狂怒，攻击附带易伤。
2. **赤魃·焚天**（火，第二幕）：灼烧与多段攻击；会把「火种」诅咒塞入玩家抽牌堆。
3. **太虚·五行主**（无，第三幕）：每回合轮转自身五行，改变弱点；半血后攻势更烈，并以「归墟」压制玩家。

## 5. 交互与界面

### 5.1 屏幕

标题 → 角色选择 → 地图 → 战斗/事件/商店/休整/宝箱 → 奖励 → 下一节点 → … → 胜利/失败。

覆盖层：牌组查看、遗物列表、图鉴、设置、暂停。

### 5.2 战斗界面

- 顶部：敌人区，显示名称、元素、生命、护甲、状态、意图（图标 + 数值）。
- 中部：五行轮盘（当前五行 → 下一可续元素）、连携层数、周天进度。
- 左侧：角色头像、生命、护甲、状态、遗物。
- 底部：手牌扇形排列；左下抽牌堆，右下弃牌堆/消耗堆；右下结束回合。
- 右侧：灵气珠、丹药腰带。
- 手牌悬停放大；点击出牌；多敌人时点击目标。键盘 1–9 出牌，E 结束回合，Esc 关闭覆盖层。
- 卡面显示动态预览（计算后的伤害/格挡、是否克制）。

### 5.3 视觉与音效

- 水墨深色背景（#0d0f12 系）、宣纸色卡面、宋体标题。
- 五行色：木 #4f9d69、火 #d4543f、土 #c39a54、金 #e6dcc3、水 #4f7fa8。
- 卡牌、按钮、节点用 CSS 渐变与纹理，不依赖外部图片或字体。
- 动画：抽牌、出牌、伤害飘字、受击抖动、连携脉冲、周天全屏波纹、Boss 阶段转换。
- WebAudio 合成音效：点击、出牌、命中、格挡、连携、周天、胜利；可静音。

### 5.4 响应式

- 目标 1280×800，最低 1024×700 可完整操作。
- 小屏时手牌缩小、侧栏折叠；不要求移动端完美适配，但不得溢出不可操作。

## 6. 技术设计

### 6.1 文件结构

```
index.html
css/style.css
js/data.js      // 静态数据：五行、卡牌、遗物、敌人、事件、角色
js/engine.js    // 纯逻辑：状态、战斗、地图、奖励、存档序列化（UMD，可 Node 测试）
js/ui.js        // 渲染、动画、音效、输入
js/main.js      // 启动与屏幕切换
test/engine.test.js
test/sim.js
README.md
```

- 全部为经典脚本（非 ES module），保证 `file://` 直接打开可用。
- `engine.js` 不访问 DOM；通过事件数组（log）向 UI 汇报结算过程。
- 引擎 API 示例：
  - `createRun(characterId, ascension)`
  - `startCombat(state, enemyIds)`
  - `playCard(state, handIndex, targetIndex)`
  - `usePotion(state, potionIndex, targetIndex)`
  - `endTurn(state)`
  - `enemyTurn(state)`
  - `finishCombat(state)`
  - `generateMap(act, rng)`
  - `save/load`
- 玩家操作后返回 `{state, events}`；事件用于动画与日志。
- RNG 用可序列化的种子（mulberry32），保证刷新后结果一致。

### 6.2 状态模型

```js
{
  version: 1,
  seed, rngState,
  characterId, ascension,
  hp, maxHp, gold,
  deck: [cardInstance], // {uid, id, upgraded}
  relics: [relicId], potions: [potionId],
  map: {act, nodes, paths, position, visited},
  combat: {
    turn, phase, energy, maxEnergy, block, statuses,
    hand, drawPile, discardPile, exhaustPile,
    enemies: [{id, hp, maxHp, block, statuses, intent, patternIndex, element}],
    currentElement, chain, cardsPlayedThisTurn, ...
  },
  log: [...],
  screen: 'map'
}
```

- 存档键：`wuxing_save_v1`，每次状态变化后节流写入。
- 元数据键：`wuxing_meta_v1`（最高天劫、图鉴、设置）。

### 6.3 数据驱动

卡牌效果声明为操作数组：

```js
{ id, name, element, cost, type, rarity, text,
  effects: [{op:'damage', value:6}, {op:'status', status:'burn', value:2, target:'enemy'}],
  upgrade: { cost:0, effects:[...] },
  exhaust, retain, character }
```

引擎解析 op：`damage, damageAll, block, draw, energy, heal, status, statusAll, loseHp, addCard, multiplyStatus, cleanse, gainMaxHp, upgradeHand` 等。

### 6.4 错误与边界

- 非法操作（灵气不足、目标失效、非战斗阶段）返回 false 且不改变状态。
- 手牌上限 10；超出上限的抽牌不进入手牌，留在抽牌堆顶部。
- 抽牌堆空时洗回弃牌堆；两者皆空则不抽。
- 敌人全灭立即结束战斗，不再执行剩余意图。
- 玩家死亡立即结束，禁止继续操作。
- 刷新页面：若存在战斗存档，恢复到最近一次操作后的状态；动画不重放。
- 事件/商店的随机结果在进入节点时生成并存入存档，避免刷新重摇。

## 7. 测试与验收

### 7.1 自动化

- 数据校验：所有卡牌/遗物/敌人/事件 id 唯一；引用的状态、元素、卡牌存在；升级数据完整。
- 连携：首牌无加成；相生 +1 并加伤；断链归零；无元素不改变链；5 层触发周天并清零。
- 相克：×1.5、无视护甲、多目标分别判定。
- 状态：中毒/灼烧递减、虚弱/易伤倍率、护甲清零与保留。
- 抽弃牌：洗牌、手牌上限、消耗、保留。
- 地图：每层连通、起点可达 Boss、节点类型合法、三幕生成稳定。
- 存档：序列化/反序列化后状态一致，可继续。
- 模拟：随机策略自动跑 500 局，无异常、无死循环、胜率在合理区间。

### 7.2 手动验收

- 三种角色各完整通关一次（可用调试模式）。
- 每个屏幕可进出、返回不丢状态。
- 1280×800 与 1024×700 下无遮挡、按钮可点。
- 刷新续局、静音、图鉴、天劫解锁正常。
- 无控制台报错。
